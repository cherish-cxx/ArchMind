## 0. 一句话原则

> **微服务 / MQ 决定你「看起来多好」，八股 / 算法决定你「能不能拿到」。**

前者是锦上添花，后者是雪中送炭。搞反顺序的代价：一个很漂亮的简历，和一次很惨的笔试。

## 2. 核心判据：offer 是**连乘**，不是累加

```
拿 offer = 过简历关 × 过笔试 × 过技术面
```

**任何一环是 0，总分就是 0。** 这就是「项目漂亮但拿不到实习」的原因——不是项目不够好，是卡在别的环节。

### 每种加成影响哪一关

| 补的东西 | 影响哪一关 | 边际价值 |
|---|---|---|
| **算法** | **笔试** + 技术面手写 | 🔴 **极高**（笔试硬门槛，挂了后面全白搭） |
| **八股** | **技术面主力，占 40–50%** | 🔴 **极高** |
| 微服务 / MQ / 高并发 | 简历关键词 + 项目深挖 | 🟡 中等 |

### 三个场景对照

| 场景 | 简历关 | 笔试 | 技术面 | 结果 |
|---|---|---|---|---|
| **A. 项目很强（含微服务/MQ）+ 算法 0 + 八股 0** | ✅ | ❌ **挂** | 没机会 | **拿不到** |
| **B. 项目一般 + 算法强 + 八股强** | 🟡 | ✅ | ✅ | **能拿到中厂** |
| **C. 全强** | ✅ | ✅ | ✅ | 中厂稳，大厂有机会 |

> **A 是最常见的失败模式。** 每年都在发生。

## 3. 优先级排序 + 时间账

| 优先级 | 做什么 | 时长 | 为什么这个顺序 |
|---|---|---|---|
| **1** | **算法** | ~100h（200 题） | **唯一突击不出来的**，需要 6+ 个月积累。**现在就开，每天 1 题** |
| **2** | 项目做深（微服务演进、MQ 改造） | ~80h | 大三上从容做，是学习不是交付 |
| **3** | **八股** | ~120h | 1–2 个月的短期记忆任务，**背早了会忘**，寒假启动足够 |

**同样 80 小时，花在算法上 vs 花在微服务上，offer 转化率差 3–5 倍。**

### 反直觉但省时间的一点

**对实习岗，「原理理解」比「动手做过」更值钱：**

| 做法 | 成本 | 面试表现 |
|---|---|---|
| 动手搭一套 MQ | ~40h | "我用了 Kafka" → 追问"消息积压怎么排查" → **没遇到过，答不上** |
| 读透 MQ 原理 | ~5h | "没用过，但我知道可靠性靠生产端确认+持久化+手动 ack，重复消费靠幂等键" → **答得稳** |

**实习面试考的是你懂不懂原理、能不能学，不是有没有生产经验。**

## 5. 项目侧的硬停止线 ★

**「完成」的定义（不要用「完善」这种模糊标准，它是拖延陷阱）：**

> **P0–P4 跑通 + 能用 curl 演示完整链路**：
> `POST /api/agent/ask` → 返回 `message + uiCommands + steps`

**到这一步就停。** 前端（P5）、容器化（P6）、SSE（P7）都是之后的弹性项。

理由：
- **面试官不会要求你现场跑前端。** 一个能讲清楚的后端闭环，比一个跑起来但讲不清的全栈 demo 值钱
- 约 60h 收尾，**这就是项目的硬上限**。别让它涨到 200h

**参考（P 级定义见设计文档 §8）：**

| 范围 | 内容 | 估时 |
|---|---|---|
| **后端闭环（必达）** | P0 清障 + P1 工具 API + P2 Python 骨架 + P3 Intent/循环 + P4 网关/Context | 7–11 天 |
| 前端闭环（弹性） | P5 MapCanvas store 化 + AIPanel 接线 + UICommand 执行 | 3–7 天（**真变数在这里**） |

**国庆目标**：以「后端闭环跑通」为界。

## 6. 投递节奏

**「找实习」不是状态，是动作。** 拆成可执行的：

| 动作 | 频率 | 说明 |
|---|---|---|
| 简历定稿 | 一次（寒假前） | 见 §7 |
| **投递** | **每周固定一天，投 10 家** | 不固定就会变成「一直没投」 |
| 笔试 | 收到就做 | — |
| **面试复盘** | 每场后 30min | 见 §8，**这是最高杠杆的动作** |

**日常实习 vs 暑期实习：**

| | 日常实习 | 暑期实习 |
|---|---|---|
| 时间 | **全年可投** | 3–5 月集中 |
| 门槛 | **低得多** | 高，大厂主通道 |
| 策略 | **寒假前后拿一段**，写进暑期实习简历 | 大三下主战场 |

**主攻中厂**：大厂初筛学历权重高；中厂学历门槛稍宽，项目质量真正起作用。

## 7. 简历写法

**公式：做了什么 + 技术难点 + 数字。** 你的数字是现成的，别浪费。

| ❌ 别这样写 | ✅ 应该这样写 |
|---|---|
| 实现了代码分析功能 | 基于 JavaParser 构建三阶段 AST 流水线（声明提取 → 索引字典 → 关系消解），在 178 文件的真实项目上产出 181 类节点 / 186 调用边，人工对拍验证 |
| 做了 AI 问答 | 设计 Agent 工具层：Neo4j 变长路径查询 + 类级折叠为 LLM 提供结构化调用链，建立 evidence 校验机制抑制幻觉 |
| 优化了接口性能 | 将同步阻塞的 analyze 接口改造为异步任务系统（任务队列 + 状态机 + 进度轮询），解决请求线程占满导致的用户白屏 |
| 用了 Redis | 接入 Redis 做项目概况缓存（TTL 30min）+ 基于 SETNX 的项目级并发锁，防止同一项目重复分析 |

### 可用的真实素材（从项目里挖，已核对）

- **AST 解析**：178 java 文件 → 181 Class + 288 Method 节点；186 CALLS + 116 DEPENDS + 16 IMPLEMENTS + 7 EXTENDS 边。短名撞车歧义处理、按 receiver 形态分派调用解析（变量/this/super/裸/静态/构造器）
- **工程约束**：Neo4j 社区版不支持 `NODE KEY`（企业版专属）→ 改用复合 `UNIQUE` 约束；JavaParser 3.25 无 `JAVA_21` → 用 `BLEEDING_EDGE`
- **设计取舍**：AST「宁可漏不要错」——外部依赖/歧义/复杂表达式一律丢弃，只连项目内确定性关系
- **异步任务系统**：task 表 + 状态机 + `@Async` 线程池 + Redis 双写进度，解决同步 analyze 占满 Tomcat 请求线程
- **双库架构**：MySQL 存关系数据 + Neo4j 存代码图，按数据类型选型

## 9. 明确不做的事 ★

| 不要做 | 为什么 |
|---|---|
| **搭「Spring Cloud + Nacos + Sentinel + Seata + RocketMQ」全家桶项目** | 面试官一眼看出是照教程敲的；必然被问「为什么用 Nacos 不用 Eureka」，答「教程用了」就完了；**且会抢走主线时间** |
| **为了「有经历」硬搭 MQ** | 对实习岗，原理理解的价值 ≈ 动手，但成本差 8 倍（§3） |
| **八股提前太久** | 1–2 个月保质期，背早了到面试时忘光，等于白背 |
| **等项目「做完」才投递** | 永远做不完。投递和项目可以并行 |
| **在简历上写了却答不上** | 写了微服务就会被问分布式事务/幂等/消息可靠性。**答不了就别写**——被问穿比不写更糟 |
| **项目无限加功能** | 边际收益极低（§2），且挤占八股算法时间 |
