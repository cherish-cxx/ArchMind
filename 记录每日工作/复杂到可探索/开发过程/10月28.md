java端已经完成描述补齐功能；
pending== 0触发条件由java侧进行触发，python侧接受后进行二次请求，校验pending。

```
分析成功 → 描述补齐任务 → pending == 0
        → Java 调 Python: POST /internal/index {projectId, rev}
Python: 先自己查一次 /internal/describe/status
        pending > 0 或 analysisStatus != COMPLETED → 不索引，返回 not_ready
        rev == 已索引的 rev → 直接返回 up_to_date
        否则开始全量拉取 + 建索引
```

拉取接口：都必须带projectId，需要约束拉取范围。同时python侧Qdrant得delete/upsert都带projectId，不能存在全部拉取的行为

python侧批量拉取，拼卡片，embed的流式做法

不需要全部进行拉取完后再进行拼卡，卡片是单个类的纯函数：
```
卡片 = description（有则用）
     否则 结构化兜底：类型 + 类名 + 包 + 方法名
```

能够做流式处理的原有：类之间没有依赖，所以按页流式处理：

```
1. status 校验通过，记下 rev
2. 按 uid 游标分页拉取（每页 200）
3. 每页 → 拼 200 条卡片文本
4. 每 32 条 → POST /embed（容器内部 batch_size=8）
5. 每 64 个 point → upsert Qdrant
6. 循环到没有下一页
7. 校验 count == describable，记录 indexedRev
```
