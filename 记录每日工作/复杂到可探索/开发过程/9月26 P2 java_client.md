## 全量JSON和流式

这两个词指的是HTTP响应拿到手之后，怎么读它：
```
你发请求 ──▶ Java 处理 ──▶ Java 开始往回吐字节
                                    │
                          ★ 分歧点在这里：
                            是"全部收完再解析"，
                            还是"边收边解析'
```

**全量**（buffered）：
	流程：把整个响应体全部读进内存，变成一个完整的JSON字符串，解析成dict，pydantic校验

**流式**（streaming）：
	流程：不把整个个体放进内存，来一块处理一块
	特点：内存占用恒定；拿到第一个字节就能开始干活


### 什么时候需要用到流式？

响应体巨大，导出几百MB数据
服务器主动推送 SSE/websocket
边收边落盘  备份下载


## 计算机网络基础

一个HTTP协议包括：
请求方法： POST GET DELETE
请求目标：/api/users
HTTP Version：HTTP/1.1

请求头：
- 内容的类型（content-Type）：application/json
- 认证凭证：？？？

空行

请求体：
- 对于POST请求，DELETE等需要参数/数据才能够完成的业务内容就需要请求体参与数据内容传输
- 对于GET则不存在请求体

### 请求从前端发出，到后端，经历了什么？

1. http请求由javaScript创建（应用层）
2. 网络发送IP包需要目标IP，需要DNS：将域名转成IP地址
```
浏览器 DNS Cache
       ↓
操作系统 DNS Cache
       ↓
DNS Resolver
       ↓
Root DNS
       ↓
.com DNS
       ↓
example.com DNS
```

最终得到类似：
```
api.example.com → 203.0.113.10
```
于是浏览器知道，把数据发到203.0.113.10

这里的DNS只是一套能够找到目的IP的网络通信

3. 建立连接（浏览器建立TCP连接）
		HTTP---TLS---TCP---IP

4. TLS
	HTTPS是TLS加密后的HTTP
	
	TLS涉及：
	- 证书
	- 身份认证
	- 密钥协商
	- 对称加密

5. TCP把数据切成TCP Segment
	
	HTTP层产生的数据交给TCP，TCP会把它作为字节流进行传输。
	
6. IP层
	
```
┌──────────────────────┐
│ IP Header            │
├──────────────────────┤
│ TCP Header           │
├──────────────────────┤
│ TLS Data             │
└──────────────────────┘	
```

7. 数据链路层

	IP数据包需要通过具体的网络链路发送
	
	于是会封装：
```
┌──────────────────────────┐
│ Ethernet Header          │
├──────────────────────────┤
│ IP Header                │
├──────────────────────────┤
│ TCP Header               │
├──────────────────────────┤
│ TLS Data                 │
├──────────────────────────┤
│ Ethernet Trailer / FCS   │
└──────────────────────────┘
```
这时候才成为通常所说的：帧Frame
    
8. 网卡发送
```
内存中的数据
      ↓
网卡
      ↓
电信号 / 光信号 / 无线电波
      ↓
交换机
      ↓
路由器
      ↓
Internet
      ↓
目标网络
      ↓
服务器
```
