# R8 角色抽查报告（2026-11-25）

> 审计对象：`RoleClassifier` 的六角色分类（入口 / 业务 / 领域模型 / 基础设施 / 外部依赖 / 未归类）。
> 不覆盖：业务领域划分、能力生成、描述质量。
> 数据源：远端 Neo4j 中已分析完成的图（只读）。
> 判定方式：依据类级注解、包名、类名、父类型与方法名逐条判断「最合适的角色」。这不是人工逐行读源码的签核；hmall 源码不在本机，`PayStatusListener` 的依据是方法名与包名。

| demo（R8 E2E） | 2125564075029893122 | 1 | 10 | 总数不足 20，全量 | 10 |

Cypher：

```cypher
MATCH (c:Class {projectId:$pid})
OPTIONAL MATCH (c)-[:BELONGS_TO]->(a:BusinessArea {projectId:$pid})
OPTIONAL MATCH (c)-[:EXTENDS|IMPLEMENTS]->(p:Class {projectId:$pid})
RETURN c.uid AS uid, c.name AS name, c.packageName AS pkg,
       c.annotationNames AS anns, c.role AS role, c.roleBasis AS basis,
       c.kind AS kind, c.isAbstract AS abs, a.uid AS areaUid, a.name AS areaName,
       collect(DISTINCT p.name) AS parents
ORDER BY c.uid
```

## 4. 修复前结论（2026-11-25 首次抽查）

| 口径 | 数值 |
|---|---|
| hmall 错误率 | 4 / 20 = 20% |
| demo 错误率 | 0 / 10 = 0% |
| 合计错误率 | 4 / 30 = 13.3% |
| 验收线 | ≤ 10% |
| **结论** | **未达标**（存疑类再计错则合计 16.7%） |

`OTHER` 是风险最大的桶：hmall 全量 21 个 OTHER（11.6%），本次抽到 4 个，其中 3 个是真实错误。按这个比例外推，hmall 可能还有十几处角色误分。

## 5. 根因与修复建议

| 根因 | 影响的样本 | 建议 | 风险 |
|---|---|---|---|
| 包名段只认 `util`，不认 `utils` | JwtTool | `PACKAGE_SEGMENT_ROLES` 增加 `utils → INFRASTRUCTURE` | 低 |
| 包名段未覆盖 `enums` | PayChannel | 增加 `enums → DOMAIN_MODEL`；或对 `kind=ENUM` 且非纯常量类做专门判断 | 中：全局常量枚举也会进领域模型 |
| `gateway` 被当成外部依赖 | MyGlobalFilter | 从 EXTERNAL 包名段移除 `gateway`，保留 `client/feign/remote` 与 `@FeignClient`；由名字/注解决定 | 中：少数项目把远程客户端放在 `.gateway` |
| 方法级监听注解不可见 | PayStatusListener | 短期：`listener` 包名段 → ENTRY；长期：把方法级注解（`@RabbitListener` / `@KafkaListener` / `@EventListener`）纳入角色判定 | 短期低；长期需改快照/模型 |
| 测试/演示类混入主源码 | HutoolTest（存疑） | 不建议为单个类加规则；先修正源码位置或忽略 | 低 |

**复抽要求**：修规则后不要用这 20 个样本当验收样本，应重新等距抽 20 个未参与调参的类；原 20 个可用于回归。

## 6. 附带的非角色观察

hmall 的业务领域分布明显倾斜：基础设施 138 / 181 类，业务域合计 43 类（cart 6、item 7、pay 7、trade 12、user 11），能力 25 个。角色审计不判断领域划分，但「76% 的类落在基础设施」值得在下一轮单独看，可能导致能力覆盖面偏窄。

## 7. 复现

1. 用第 1 节的 Cypher 按 `uid` 排序取全量类。
2. 按 `round(i * (n-1) / 19)` 取 20 个下标。
3. 逐条按注解 → 包名 → 类名/父类 判定最合适角色，与本表对照。

## 8. 修复与复抽（2026-11-25 晚）

### 8.1 规则变更

| 变更 | 目的 |
|---|---|
| 入口包名段增加 `listener` | 修复 `PayStatusListener` 这类 MQ 消费者 |
| 领域模型包名段增加 `enums` | 修复 `PayChannel` 这类领域枚举 |
| 基础设施包名段增加 `utils`、`filters` | 修复 `JwtTool`、网关过滤器 |
| 外部依赖包名段移除 `gateway` | `gateway` 模块通常是网关自身；`client`/`feign`/`remote` 与 `@FeignClient` 继续判外部依赖 |

### 8.2 验证

- 单元测试：`RoleClassifierTest` 新增 5 条（utils、enums、gateway filters、listener、client 回归），全绿。
- Java 全量：172 tests，0 failures，5 skipped。
- **调参样本回归**（原 20 类）：4 个确定误判全部修正——
  `PayChannel → DOMAIN_MODEL`、`MyGlobalFilter → INFRASTRUCTURE`、
  `PayStatusListener → ENTRY`、`JwtTool → INFRASTRUCTURE`。
  `HutoolTest` 仍为 BUSINESS（存疑项，未处理）。
- **新样本复抽**（验收依据）：hmall 排除调参 20 后剩 161 类，按 `uid` 等距抽 20。

| 新样本项 | 结果 |
|---|---|
| 确定误判 | 0 / 20 = 0% |
| 灰区 | 1：`com.hmall.common.domain.R` 被判 DOMAIN_MODEL；它是通用响应包装类，更像基础设施/公共层，但包名确实含 domain。未计入错误；若计错则为 1/20 = 5% |
| demo 复跑 | 10 类全量，0 错误 |
| 验收线 | ≤ 10% |
| **结论** | **通过**（0% 或严格口径 5%） |

### 8.3 限制

- 新规则目前只在**离线复抽**中验证；hmall 图里保存的 `role` 仍是旧值，需要重新分析（或重跑 DOMAIN）才会写回。重分析后能力与业务领域可能随之变化。
- 方法级监听注解仍未进入判定：现在靠 `listener` 包名兜底。若监听类不在 `listener` 包、类级也没有注解，仍会落 `OTHER`。下一轮可把方法注解写入快照/图后，再做真正的注解级判定。
- 调参用的 20 类不能当作验收样本；验收以本节新抽的 20 类为准。
